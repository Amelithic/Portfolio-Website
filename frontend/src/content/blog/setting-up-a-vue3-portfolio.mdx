Every portfolio site starts as a blank page, and deciding how to structure the code before writing any of it saves a lot of pain later.

I settled on a domain-based layout: the blog and projects live in their own folders, each with their own router, components, and views. The main router simply imports those sub-routers, so adding a new section later means creating a folder, not rewiring the whole app.

Content is typed with TypeScript interfaces and stored as plain data for now, which keeps things simple while leaving room to swap in a markdown pipeline or a real backend later.
